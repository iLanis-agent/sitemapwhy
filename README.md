# SitemapWhy
Paste a sitemap.xml or sitemap index: well-formed XML or not, schema pass or fail with line numbers, and (given the file's location) which URLs search engines would drop. Static client-side app, open `app.html`.
Sources: https://www.sitemaps.org/protocol.html (read in full) and the schema files http://www.sitemaps.org/schemas/sitemap/0.9/sitemap.xsd and siteindex.xsd (downloaded, used as the oracle).
Tests: `oracle.py <seed> <n> <out.jsonl>` generates sitemap-like documents with many mutations (missing namespace, bad dates, bad URIs, raw ampersands, wrong order, broken XML) and records libxml2's (lxml) well-formedness and XSD verdicts. `node test-engine.js *.jsonl` compares the engine. Result: 180,000 documents (about 66,600 well-formed, about 14,000 schema-valid), 0 disagreements. Seeds 1 to 9 were used while fixing the engine (it started with 101 differences in the first 6,000 documents, mostly XML whitespace and namespace-URI edge cases); seeds 10 and 11 (40,000 documents) were run once after the last change. `node test-protocol.js` checks the protocol-text rules (host, protocol, port, folder, 50,000 URLs, 2,048 characters) with examples from the protocol page. Those rules were not compared with any other tool.
Limits: the XML parser is a subset (no DOCTYPE, UTF-8 only; other encoding names are rejected). The URI check imitates libxml2's lenient anyURI test, which accepts spaces and non-ASCII characters; those are reported as warnings. Search engines can be stricter or looser than the schema.
